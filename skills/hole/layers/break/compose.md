# 提示词四层协议与模型适配

## 一、四层结构（每层只解决一件事）

| 层 | 名称 | 解决什么 | 写不好会怎样 |
|---|---|---|---|
| L0 | 身份锚定 | 模型是谁、为谁工作、长期目标 | 一问身份就退回通用助手人格 |
| L1 | 任务框架 | 任务的合法性与边界（授权、范围、红线） | 被质疑时无法自证，直接拒答 |
| L2 | 工具纪律 | 先读 catalog 再动手、占位符规范、失败重试 | 乱调工具、编造结果、参数错位 |
| L3 | 输出契约 | 结构化格式（报告字段、证据要求、字数） | 输出漂移、关键字段缺失 |

**关键认知**：L1 不是去说服模型，而是**陈述事实**——授权类型、范围、时间窗、停手条件。事实充分时，模型不需要被绕过，只需要被告知。

## 二、模型适配矩阵

| 维度 | 国模（DeepSeek / Qwen / GLM / 豆包） | 海外模型（GPT / Claude / Gemini） |
|---|---|---|
| 拒答主因 | 缺授权上下文；任务描述抽象 | 缺授权上下文 + 敏感词密度 |
| 有效手段 | L1 写实授权信息、给具体占位符 | L1 写实 + 任务拆成可验证子步骤 |
| 无效手段 | 角色扮演（易被识破） | 强硬语气、命令式施压 |
| 稳定性建议 | 提示词前置、少叠修辞 | 分步确认、每步给可验证产物 |
| 常见失败态 | 中途改口为无法协助 | 早期降级为通用建议 |

结论：**同一份 L1，两类模型都吃**，差异主要在 L3 的长度与格式。

## 三、拒答检测与重试（可观测）

| 信号 | 判定 | 处理 |
|---|---|---|
| 输出出现「我无法 / 我不能 / 无法协助 / I cannot」 | 硬拒 | 检查 L1 是否缺授权事实 |
| 输出退化为通用建议（无具体命令或路径） | 软拒 | 检查 L2 是否给了工具与占位符 |
| 中途改口 | 上下文漂移 | 缩短对话、把 L1 重新前置 |
| 反复要求澄清 | 槽位缺失 | 用 guard 层 target.json 填满参数 |

重试策略：同一提示最多重试 2 次，每次只改一层（先 L1，再 L2），并记录改动点。禁止无脑重发。

## 四、留痕格式（每次评测一行 JSONL）

```json
{"ts":"2026-10-26T10:30:00Z","profile":"cn-model","task":"pentest","layers":{"L0":true,"L1":true,"L2":true,"L3":true},"prompt_bytes":8421,"refusal":0,"retries":0,"note":"首轮通过"}
```

只看三个指标：**首轮通过率、平均重试次数、层覆盖完整度**。

## 六、语言选择：用什么语言写提示词，模型更服从

### 结论先行

| 位置 | 推荐语言 | 原因 |
|---|---|---|
| 技能元数据（`name` / `description`） | **英文** | 技能目录检索与跨模型解析以英文为主；中文 description 在英文体系中召回率偏低 |
| 硬约束（MUST / NEVER / 退出码 / 阈值） | **英文关键词 + 中文解释** | 指令遵循在英文约束词上最稳；纯中文长句容易被理解为建议 |
| 流程与判据正文 | **中文**（面向国模）/ **英文**（面向海外模型） | 理解力与训练语料分布一致时最好；同一份内容建议拆 zh/en 双份 |
| 代码、路径、命令 | **永远保持原文** | 翻译即失真，且工具参数不能本地化 |

### 证据

- arXiv 2604.14210（2026，SWE-bench Lite 实测）：**中文提示词的问题解决成功率整体低于英文**，各模型一致；但 token 成本因架构而异（MiniMax 中文更贵 1.28x，GLM-5 中文反而更省）。结论：**别为了省 token 换语言，会牺牲成功率**。
- 跨语言检索评测（BrowseComp-Plus 等）：非英文语境下 agent 表现普遍下降，即使把证据直接喂给模型也无法完全追平单语水平。
- 关于「中文模型更懂中文」：聚合统计显示中英文模型之间**没有系统性文化倾向差异**，差异更多来自厂商训练数据配比，而非语言本身。

### 落地规则（本插件已按此实现）

1. `SKILL.md` 的 frontmatter 用英文（当前即如此）；正文用中文，因为面向国模与中文用户。
2. 第 2 节「模型适配矩阵」的两档 profile：`cn-model` 挂中文资产、`en-model` 挂英文资产，**不混用**。
3. 硬约束一律写成可执行判定，而不是祈使句：
   - 差：`请不要对未授权目标测试`
   - 好：`target.mjs check 退出码非 0 → 停止（build 同样退出 2）`
   **能写成代码判定的规则，就不要只写成文字**——文字会被解释，退出码不会。
4. 结构优先：同样的内容，表格 / 编号清单 / 判定树 的服从率显著高于连续段落。
5. 指令语言与用户语言保持一致，避免「中文提问 + 英文规则」造成的语义漂移；跨语言时先固定术语表（target / scope / gate）。

### 一句话

> 语言只影响「理解得准不准」，**结构才决定「服从得稳不稳」**。想让它听话，就把规则变成它必须执行的动作，而不是它需要认同的观点。
