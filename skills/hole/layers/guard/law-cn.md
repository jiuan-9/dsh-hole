# 中国法律边界与交战规则（ROE）· 防御层

> 本分册是全套技能的**前置条件**。任何一章的操作都只在满足本分册条件时才允许执行。

## 一、中国法律红线（硬约束，不讨论、不变通）

| 行为 | 触犯 | 说明 |
|---|---|---|
| 未授权访问他人系统、获取数据 | 刑法 285 条第 1 款（非法侵入计算机信息系统罪）／第 2 款（非法获取计算机信息系统数据罪） | 「我只是看看」也是侵入；读取即获取数据 |
| 对系统功能进行删除、修改、增加、干扰 | 刑法 286 条（破坏计算机信息系统罪） | 含上传 webshell、改配置、写文件、压测打到不可用 |
| 提供侵入/非法控制工具、程序 | 刑法 285 条第 3 款 | 对外传播爆破/远控工具本身即违法，即使是"技术分享" |
| 出售、提供、非法获取公民个人信息 | 刑法 253 条之一 + 《个人信息保护法》 | 拖库、导出客户名单、手机号库交易 |
| 未履行等保义务、数据泄露不报 | 《网络安全法》《数据安全法》 | 这是厂商侧义务，但影响披露流程与时限 |
| 未经授权对关键信息基础设施做渗透 | 《网络安全法》第 31 条 + 《关键信息基础设施安全保护条例》 | 旅游/票务平台若被认定为 CII，测试门槛更高 |

**唯一合法路径**：① 平台项目页明确列出该资产（补天/漏洞盒子/CNVD 专测/众测）；② 厂商书面授权（含邮件确认、测试范围、时间窗）；③ 自有系统或自建靶场。三者之外，只允许做**公开信息检索**（搜索引擎、证书透明度日志、DNS 公开记录、官网页面对外内容）。

## 二、授权核验清单（开工前逐条打勾）

- [ ] 目标域名/IP 在项目页或授权书列举范围内？注意子域是否覆盖（多数项目只覆盖主域，子域需单独确认）
- [ ] 授权是否写明**禁止项**？（常见禁止：口令爆破、社工钓鱼、DoS/压测、物理入侵、供应链）
- [ ] 是否有**测试时间窗**与**速率约定**？
- [ ] 是否要求**测试账号由厂商提供**？（涉及后台的都需要）
- [ ] **数据处置约定**：拿到敏感数据如何交付、保留多久、是否需当场删除？
- [ ] 是否要求**保密**（NDA）？报告能否公开？
- [ ] 紧急联系人（厂商侧）与**停手触发器**：一旦误触生产数据、导致服务异常，立即停并通知。

## 三、数据最小化原则（贯穿全程）

1. **只证明存在，不扩大**：能读到 1 条记录就证明越权，不要翻第 2 条；能取到表名就不要 dump 数据。
2. **不落地敏感数据**：截图时对身份证、手机号、金额做遮挡；测试账号口令不要与原系统共用。
3. **不修改、不删除、不上传持久化文件**：需要验证上传时，用无害内容 + 立即删除并记录。
4. **不做破坏性验证**：不用 `DROP`/`SLEEP` 大于 5 秒的盲注、不跑并发压测、不打 OOB 到不可控第三方。
5. **不留后门**：任何情况下不保留 webshell、不建隐藏账号。

## 四、被判定"越界"的常见情形（自保要点）

- 对**未列入范围**的子域/资产做测试 → 多数项目直接判违规，取消资格；
- 把**证明存在**升级为**实际取数**（读了 1000 条用户信息）→ 平台判违规，法律上也可能被认定"获取数据"；
- 报告里写「已爆破进入后台」但无可复现材料 → 既拿不到评级，也留下不利证据；
- 用**他人身份信息**注册测试账号 → 侵犯个人信息，与漏洞无关的独立违法；
- 测试中**误伤第三方**（如 SSRF 打到外部系统）→ 责任在测试方。

## 五、披露流程（标准四步）

1. **内部验证**：复现三遍，确认稳定，留存最小证据集；
2. **提交**：走平台渠道（厂商确认 + 定级）；无平台则发披露邮件，附最小复现信息；
3. **等待修复**：给厂商合理周期（高危 7 天、中低危 30 天），期间不公开细节；
4. **复测**：修复后按原 PoC 复测，输出复测结论（已修复/部分修复/未修复），闭环。

> 厂商超期不响应：可升级至 CNVD 报送，或按《网络产品安全漏洞管理规定》要求走工信部渠道。仍然公开细节需谨慎，避免成为"提供攻击方法"的一方。
